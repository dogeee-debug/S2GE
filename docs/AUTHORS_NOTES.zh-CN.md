## 研究动机与启发

S2GE 起始于一个刻意保持简单的问题：什么样的最小图任务，能够判断语言模型
是否真正使用了暴露给它的拓扑结构？

我们选择最短跳数预测，并不是因为“数跳数”本身就是最终目标，而是因为 HopQA
是一种小型、可检查的结构原语。许多更复杂的图任务都可以拆解为若干较小操作：
定位相关节点、判断连通性、比较路径、解释外部计算得到的结构信号，以及把这些
信号映射到下游决策。

这一视角深受软件工程思想影响。设计良好的系统会为不同组件划定有限职责，并
依赖组件之间稳定的接口。图算法不需要完成语言理解，语言模型也不一定需要在
内部重新实现 BFS、最短路搜索、中心性估计或所有其他图算法。真正重要的是，
一个组件的输出在传递给下一个组件后仍然可读、可用。

这一认识塑造了 S2GE。Query-aware sampling 决定哪些证据进入受限接口；
role-based perception 使端点、邻近节点和上下文可以区分；adjacency-based
alignment 鼓励局部结构关系在投影后继续保留。随后，解码器通过普通生成过程
消费该接口。在论文中，这三个阶段分别对应证据纳入、角色可读性和邻接可恢复性。

现代 LLM 系统越来越依赖检索系统、图引擎、符号程序、工具和数据库。外部计算
可以免除语言模型亲自执行每一种图操作的必要，但无法免除模型理解计算结果的
必要。检索器可能返回子图，图引擎可能返回路径，规划器可能暴露依赖图；最终，
仍然需要某个下游模型解释这些结果并据此行动。

因此，我们区分“图信号存在”和“解码器可用性”。在实验中，即使原生生成仍然
较弱，纯图控制和检索执行控制也能恢复有用的图信号。由此可见，解码器之前存在
有用结构，并不保证解码器能够使用它。外部计算越强，可靠的图—语言接口可能越
重要，而不是越不重要。

S2GE 并没有证明接口问题已经彻底解决。它表明这种失败可以被缓解：更谨慎地选择
查询相关证据、明确端点角色并更好地保留局部邻接关系，能够显著改善原生生成。

“Sampling first”也表达了在受限信息瓶颈下推理的观点。大型图很少被完整呈现给
语言模型，模型通常只能看到一个有界视图。接口必须决定哪些差异应当保留、哪些
信息可以舍弃。好的压缩不只是减少 token 数量，而应在去除无关信息的同时保留
与查询有关的关键差异。

一旦两种不同情形被映射成不可区分的接口，下游更大的解码器也无法重建已经丢失
的差异。这正是论文中固定接口信息边界的直觉。DBLP 采样审计给出了具体例子：
仅按度数采样无法纳入必要的端点条件证据，而 query-aware sampling 显著提高了
端点覆盖率和路径召回率。

因此，对我们而言，“sampling first”是在说明推理从哪里开始：在要求模型进行
良好推理之前，首先必须决定允许它看到哪些信息。

## 未来方向

### 从结构原语走向更强任务

我们把 HopQA 看作起点，而不是 S2GE 的最终应用。下一步可以检验同一套接口原则
是否能够支持可达性、路径比较、路径见证、图基础检索、推荐、链接推理、关系规划
等任务。这些任务都要求语言模型最终消费结构计算的结果。

目标并不是把所有下游任务都改造成另一种 HopQA，而是研究：当下游目标改变时，
可靠的结构接口能否复用。用软件工程语言说，就是能否在不重建整个接口的情况下
更换任务头。

### 更大模型

目前实验使用 LLaMA-3-8B-Instruct。受计算资源限制，我们没有系统研究不同解码器
规模，因此仍有一个开放的实证问题：观察到的失败有多少对模型规模敏感，又有
多少受到接口限制？

理论分析只说明：在暴露接口固定时，扩大解码器无法恢复已经被接口移除的差异。
它并不意味着更大模型与实验中的 8B 主干表现完全相同。我们欢迎使用更大、更强
模型对 S2GE 风格接口进行验证。

### 对优化设置的敏感性与训练动态

有一个现象是我们没有足够时间进行系统研究的：输出状态动态对优化配置较为敏感。

在开发过程中，修改数值精度和训练配置后，失败状态与高 EM 状态之间的低维转移
变得尤其明显。这一观察促使我们检查不同 checkpoint 的生成输出，而不再只关注
损失或最终准确率，并最终形成了论文中报告的输出状态诊断和 checkpoint PCA。

但是，这些配置是在开发过程中同时修改的，因此我们不把观察到的变化归因于任何
单一因素。特别是，我们没有通过受控的析因实验分别隔离数值精度和 gradient
checkpointing 的影响。

我们原本希望进行一个简单的 2x2 实验：

### 超越 Graph-LLM

我们无法确定未来研究是否会一直围绕图增强 LLM 展开，研究方向本来就会变化。
但我们仍希望 S2GE 能通过更好的诊断、更强的主干、新的下游任务和真实系统测试
继续发展。

### 一种可能的工业角色

S2GE 在工业系统中的一种可能定位，是成为外部结构化计算与 LLM 智能体之间的
接口层。外部系统可能已经能够构建服务依赖图、工作流 DAG、知识子图、编译器
调用图或数据库模式图。剩下的问题是，下游智能体能否可靠地理解并使用这些结构。

可能的架构如下：

```text
外部结构化计算 -> 拓扑可读接口 -> LLM / 智能体
```

S2GE 并不打算替代图算法。它的作用是把图算法的输出翻译成跨越图—语言边界后仍然
可用的表示。

归根结底，S2GE 不只是教 LLM 计算跳数，而是在追问一个更广泛的问题：结构化计算
应当如何跨越边界进入语言模型？

**仅有图证据还不够，真正重要的是证据是否仍然可用。**
